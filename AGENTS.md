# AGENTS.md — dotfiles-ai

Versioned bundle of [Pi](https://pi.dev) (coding agent) config, skills, and bootstrap scripts. Treat this repo as a personal dotfiles drop: files here are the source of truth; `~/.pi/agent/`, `~/.pi/gentle-ai/`, and `~/.agents/skills/` are installed copies regenerated by `bootstrap.sh`.

## Layout

- `bootstrap.sh` — install everything in one shot: Pi skills + agent skills + the `agent-browser` CLI + bundled configs + baked web-design rules + Next.js docs snapshot. Prints only curated lines; `--verbose` streams every command's output. The agent-skill clones run in a bounded pool (`DOTFILES_JOBS`, default 6).
- `agent/web-search.json` — `pi-web-access` ext config (workflow + provider defaults), copied to `~/.pi/agent/web-search.json` — the path `getWebSearchConfigDir()` falls back to when `XDG_CONFIG_HOME` is unset. Keep this file free of secrets.
- `gentle-ai/profiles.json` — `gentle-pi` provider agent-model profiles (review/agent roles mapped to `model` + `thinking`), copied to `~/.pi/gentle-ai/profiles.json` on bootstrap. Ships `Full-Code` (active), `Chill-Code`, and `Boludear`; if the runtime file exists and differs, bootstrap asks before replacing it (Enter/`y` = replace, no terminal = keep + warning, `-y` = always replace) — the bundle stays the source of truth for the default profile. Every `provider/model` id referenced here must also exist in the machine's `~/.pi/agent/models.json` — see the note below. No secrets.
- **Machine-local state, NOT managed by this bundle:** `~/.pi/agent/models.json` (custom model providers + API keys) and `~/.pi/agent/themes/` never ship here and bootstrap never touches them. A fresh machine sets up its own providers — with their keys — directly in `~/.pi/agent/models.json` (mode 600); `gentle-ai/profiles.json` roles only resolve if that file defines the referenced `provider/model` ids.
- `skills/<id>/SKILL.md` — local skills shipped with the bundle (e.g. `kalarm-cli`, `epson-xp211-control`, `math-calc`, `genmsi-modeling`); copied to `~/.agents/skills/<id>/` on bootstrap.
- `bake-web-design-rules.sh` — one-time fetch + inline of the `web-design-guidelines` rulebook so reviews work fully offline.
- `generate-next-docs.sh [version]` — snapshot `next@<version>/dist/docs/` into `~/.agents/skills/nextjs-docs-v<sanitized>/` (dots in the semver version become dashes in the slug, e.g. `16.3` → `nextjs-docs-v16-3`).
- `.atl/skill-registry.md` — generated index of all reachable skills. Do not hand-edit.

## Commands

```sh
./bootstrap.sh                          # install everything (quiet, curated output)
./bootstrap.sh --verbose                # same, streaming every command's output
./bootstrap.sh -y                       # always overwrite the copied configs; for unattended runs
DOTFILES_ASSUME_YES=1 ./bootstrap.sh    # same as -y, for an environment that already exports it
DOTFILES_JOBS=4 ./bootstrap.sh          # tune concurrent skill clones (default 6, 1 = sequential)
NEXT_DOCS_VERSION=15.5 ./bootstrap.sh   # pin Next.js docs version for this run
./bake-web-design-rules.sh              # (re)bake web-design rules offline
./generate-next-docs.sh 16.3            # rebuilds nextjs-docs-v16-3 (dots in version → dashes in slug)
```

After `bootstrap.sh` finishes, restart Pi (or run `/reload`) so it picks up the new skills and config.

## Conventions

- **Bundle vs runtime.** Everything under `~/.pi/agent/`, `~/.pi/gentle-ai/`, and `~/.agents/skills/` is installed state. Edit here, then re-run `bootstrap.sh` to refresh. Never edit the installed copies directly — they will be overwritten. **Exceptions (machine-local, never installed from the bundle):** `~/.pi/agent/models.json` and `~/.pi/agent/themes/` hold per-machine state (API keys, visual prefs) and bootstrap does not manage them.
- **Local vs upstream skills.** Add a local skill under `skills/<id>/` when it must ship offline, depend on bundled assets, or be tweaked beyond what upstream ships. Add it to `AGENTS_SKILLS` (or `PI_SKILLS`) in `bootstrap.sh` when it lives upstream and is fetched from a remote.
- **Pinning remote refs.** Always pin the git ref in `AGENTS_SKILLS` (`|main`, `|canary`, or a tag). Bare entries silently track upstream HEAD, which makes the bootstrap non-reproducible. **One deliberate exception:** the `agent-browser` CLI installs at `npm ...@latest` (see the **Skill runtime prerequisites** entry below) — do not "fix" it into a pinned version without reading that entry first.
- **Quiet output is the contract.** `bootstrap.sh` prints only curated lines — section headers, one `✓` per installed item, `?` for the one interactive overwrite question per prompt, and `!` for warnings. Third-party output (`git clone`, `pi install`, helper scripts) is captured by `run_quiet` and discarded on success. Route new steps through `run_quiet` instead of redirecting to `/dev/null` (git writes its banner and progress to **stderr**, so `>/dev/null` alone does not silence it). Use `--verbose` or `DOTFILES_VERBOSE=1` when debugging; failures dump the captured output and write a log under `$XDG_STATE_HOME/dotfiles-ai/`.
- **Agent-skill installs run in a bounded pool.** The `AGENTS_SKILLS` loop clones up to `DOTFILES_JOBS` skills at once (default 6) and replays the curated `✓` lines in declaration order after the barrier, so output stays deterministic. Anything that mutates **shared** state must stay outside the pool: `~/.pi/agent/settings.json` (the reason `pi install` is sequential — it read-modify-writes the shared `packages` array), a shared `node_modules`, or a single target directory. Jobs get `GIT_TERMINAL_PROMPT=0` and `</dev/null`, so a credential prompt fails fast instead of hanging or eating stdin. `DOTFILES_JOBS=1` and `--verbose` use the sequential path.
- **No receipt-driven development in this repo.** The clone-local review switch is off (`gentle-ai review mode disable --scope clone`), which overrides the global default. Do not run the native review preflight (`gentle_review` inspect/START) for candidates here and do not re-enable the switch for this clone; check with `gentle-ai review mode status`. Other repositories keep the global default.
- **Commit cadence.** Commit after changing `bootstrap.sh`, any `*.sh` script, agent config, or local skills — these are the files that _change_ the installed environment.
- **Secrets.** Never commit secrets — that includes API keys in any form. Model-provider keys live only in the machine-local `~/.pi/agent/models.json` (mode 600), which this bundle does not track. If a token or credential ever lands in this repo by accident, rotate it and scrub the full git history (`git filter-repo` or BFG) before pushing. Keep key `export`s out of any repository-tracked shell rc: a `600` file outside a repo, sourced from the rc, has a much smaller blast radius.
- **Skill runtime prerequisites.** Each remote skill may declare runtime deps. Currently bundled:
  - `firecrawl/anydoc` needs Node 20+ on PATH (used via `npx -y @firecrawl/anydoc`); OCR hosted mode additionally needs `FIRECRAWL_API_KEY`.
  - `next-dev-loop` (from `vercel/next.js|canary`) needs `agent-browser >= 0.31.1` on PATH — a hard floor: the skill refuses to run without it rather than fall back to a weaker probe. `bootstrap.sh` installs the CLI at `@latest` **on purpose**: the skill tracks Next.js canary and keeps raising that floor, so a pinned CLI goes stale and breaks the skill. The skill also needs Next.js 16.3+ with Turbopack and a running `next dev`.
  - `mmx-cli` (from `MiniMax-AI/cli`, installed as `~/.agents/skills/mmx-cli/`) needs the `mmx` CLI on PATH (`npm install -g mmx-cli`) and a MiniMax API key (`mmx auth login --api-key sk-…`, or `MINIMAX_API_KEY` in the environment). `bootstrap.sh` installs the skill only — the CLI and its credentials are per-machine and stay out of the quiet bootstrap.
  - `genmsi-modeling` (local, installed as `~/.agents/skills/genmsi-modeling/`) needs the GenMSI engine on PATH: the `genmsi` binary, which also serves the MCP tools the skill drives (`catalogue`, `lint`, `simulate`, `explain_model`, `get_trace`, `open_model`, `save_model`). `bootstrap.sh` installs the skill only — the binary and the MCP registration (`pi mcp add genmsi -- <path-to-genmsi> mcp`) stay per-machine, like the `mmx-cli` and `math-calc` runtimes.
  - `math-calc` (local, installed as `~/.agents/skills/math-calc/`) needs `python3` on PATH — the only hard requirement. `sympy` (for the `exact`, `simplify`, `diff`, `int` and `solve` modes) and `bc` (for the `bc` mode) are optional; a missing engine exits with code 3 and prints the install command in `HINT:`. `bootstrap.sh` installs the skill only — the engines stay per-machine. Run `~/.agents/skills/math-calc/scripts/calc --check` to see which engines are present, and `bash ~/.agents/skills/math-calc/scripts/selftest.sh` for the skill's own test suite.
  - A browser backend is still required at runtime. `bootstrap.sh` deliberately does **not** download one: agent-browser auto-detects an existing Chrome / Brave / Chromium / Playwright install, and on a machine with none the cold path is a one-time, several-hundred-MB, per-machine step run by hand — `agent-browser install` (`--with-deps` when the system libraries are missing; that one needs the package manager, i.e. sudo, which is why it stays out of the quiet bootstrap). Check the current state with `agent-browser doctor`.
  - When adopting skills with new system deps, list them here.

## Edit boundaries

- **Safe to edit:** `bootstrap.sh`, `bake-web-design-rules.sh`, `generate-next-docs.sh`, `skills/*`, `agent/*`, `gentle-ai/*`, this file.
- **Do not edit:** `.atl/skill-registry.md` (regenerate via Pi's `/skill-registry:refresh`), `~/.pi/agent/*`, `~/.pi/gentle-ai/*`, `~/.agents/skills/*` (installed copies; will be overwritten by `bootstrap.sh`).
- **Generated runtime state:** `.atl/` is gitignored. Do not commit it; do not rely on it being present on another machine.

## Adding a new skill

1. **Local-first** — create `skills/<id>/SKILL.md` (and any `assets/` or `references/` it needs). Re-run `./bootstrap.sh` to copy it into `~/.agents/skills/<id>/`.
2. **Upstream** — append the URL to `AGENTS_SKILLS` in `bootstrap.sh`. Use the `repo|subpath|ref` form for monorepo sparse installs.
3. **Refresh the index** — restart Pi and run `/skill-registry:refresh` so `.atl/skill-registry.md` lists the new skill.

## Adding a new Pi extension

- **Extension** — append the npm or git URL to `PI_SKILLS` in `bootstrap.sh`. Pi's `pi install <url>` handles the rest.
- **Config JSON** — drop the JSON file under `agent/` or `gentle-ai/` and re-run `./bootstrap.sh`. The script copies it into the matching `~/.pi/agent/` or `~/.pi/gentle-ai/` location. (Model providers and themes are machine-local — see the note in Layout.)
