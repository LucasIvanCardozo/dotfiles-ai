# Plasma 6 / KDE Gear 26.08+ Calendar CLI Changes

What changed from Plasma 5 → 6 that breaks the classic `kalarm` + `konsolekalendar` workflow.

## Removed: `konsolekalendar`

KDE dropped the CLI from the `korganizer` package. The binary `konsolekalendar` does NOT exist anymore in `/usr/bin/`. Only the SVG icons remain in `/usr/share/icons/`.

**Replacement**: `khal` (Python CLI in the official Arch repos). Reads/writes iCalendar/vdir files directly, no Akonadi dependency.

## `kalarm` CLI 3.13.1 (KDE Gear 26.08) has known bugs

Verified on CachyOS / KDE Gear 26.08.0 / kalarm 3.13.1:

| Command | Behavior |
| --- | --- |
| `kalarm --list` | works (lists alarms) |
| `kalarm --time "YYYY-MM-DD HH:MM" --reminder 1H "text"` | fails: "Parámetro no válido «--time»" |
| `kalarm --korganizer "text"` (without `--time`) | segfault (exit 139) |
| `kalarm --help` | works |

**Workaround**: prefer `khal new ... -m 1H` for adding events with alarms. The `VALARM` blocks land in the vdir files; a future notification daemon (Phase 2) can pick them up.

If `kalarm` is fixed upstream, the vdir files generated by khal are compatible — no migration needed.

## Akonadi service unit rename

`akonadi.service` does NOT exist as a systemd user unit. The actual unit is `akonadi_control.service` (marked `static` — `systemctl enable` is rejected).

**Correct start**:

```bash
akonadictl start
```

`akonadictl` triggers the DBus-activated control agent. Modern Akonadi starts on-demand when any client (KAlarm, KOrganizer) requests it.

## `khal` 0.14+ CLI changes (relevant)

| Old | New | Note |
| --- | --- | --- |
| `khal add ...` | `khal new ...` | renamed |
| `khal agenda ...` | `khal calendar ...` | renamed |
| `khal --category TAG` | `khal -g TAG` (comma-separated) | flag shortened |
| `khal list` accepts `today +7 days` | NO — only absolute `YYYY-MM-DD` | use `date -d` first |
| `[default] default_duration` | removed | config key gone |
| `[view] agenda_view` | removed | config key gone |
| `[calendars] type = filesystem` | use `type = calendar` | filesystem type removed |
| `[calendars] type = vdir` | use `type = calendar` | unified under `calendar` |

## What still works as documented

- `khal list`, `khal search`, `khal edit`, `khal new`, `khal calendar`
- `--format "{start-date}|{title}"` (custom format for parsing)
- `--once` (no event repetition in output)
- `-r weekly|daily|monthly|yearly` + `-u DATE` for recurrence
- `-m 1H,15M` for VALARM blocks

## Migration path

If you have legacy `konsolekalendar` workflows or `kalarm` events:

1. Export KOrganizer events to `.ics` (File → Export)
2. Convert single-file to vdir: `mkdir ~/.calendars/personal && for ev in *.ics; do icalendar-splitter "$ev" ~/.calendars/personal/; done`
3. Configure khal to point at the new directory (see `khal-queries.md`)
4. Re-add events with native KDE alarms via KOrganizer GUI (one-time effort)
